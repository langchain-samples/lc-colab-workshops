# Contributing

## The notebook contract

Every lesson obeys these. `python3 tools/check_notebooks.py` enforces the mechanical ones.

1. **Cell 0 is the Colab badge**, pointing at `main` and at this notebook's own path. Paths are
   permanent: a badge URL gets pasted into decks and chat, and renaming a file breaks every copy.
2. **Cell 1 says what you'll build** — the agent and the artefact, never the API surface.
3. **A notebook depends on nothing but PyPI.** No cloning, no `curl`, no imports from this repo.
   Colab fetches only the `.ipynb`; everything else the notebook creates itself.
4. **One setup cell**, identical in shape everywhere: install, read `LANGSMITH_API_KEY` from
   Colab Secrets with a `getpass` fallback, set a per-lesson `LANGSMITH_PROJECT`, define `MODEL`.
5. **`MODEL` is one named constant** per notebook, so a gateway model rename is one line.
6. **Teaching-relevant text is visible.** `AGENTS.md`, `SKILL.md`, prompts, and tool docstrings
   go in `%%writefile` cells — never generated by a helper, never behind a form cell.
7. **Bulk data goes in a Colab form cell** (`#@title ... { display-mode: "form" }`), which
   renders as a one-line title and expands on double-click. Data must still be small enough to
   read: participants who cannot check the data cannot check the agent.
8. **Outputs are stripped** before commit. Clean diffs, and no committed tunnel URLs, workspace
   IDs, or traced payloads.
9. **Only `LANGSMITH_API_KEY`.** A notebook that needs a second credential has broken the
   course's central promise.
10. **Fixed closing structure:** checkpoints throughout → one exercise with an inline solution →
    key takeaways → next link. (`00_setup` is exempt; it is a preflight, not a lesson.)

## Paths

Use **relative** paths (`agent_home/skills/...`), not `/content/...`. Colab's working directory
is `/content`, so relative paths resolve correctly there *and* locally.

`%%writefile` does not create parent directories — it is a plain `open(path, "w")`. Any nested
write needs `!mkdir -p` first. This bites hardest with skills, which are directories.

## Screenshots

Until a PNG exists, a screenshot ships as a placeholder blockquote carrying the final filename,
the capture instruction, and the caption that survives:

```markdown
> 📸 **`06-studio-approval`** — Studio thread paused on an `issue_refund` interrupt, with the
> Approve / Edit / Reject controls visible.
>
> *Caption:* The same interrupt you resumed in code, resumed from the UI instead.
```

`tools/check_notebooks.py` prints outstanding placeholders as a checklist. Replace one by
dropping the PNG into `assets/screenshots/` and swapping the blockquote for an image using an
**absolute** raw URL — Colab cannot resolve repo-relative image paths.

## Repeated blocks

Self-containment means the setup cell exists 15 times and the support-agent fixture 6 times.
Canonical text lives in `scratch/nbkit.py`; notebook copies are wrapped in markers:

```python
# --- snippet:support_agent v1 ---
...
# --- /snippet ---
```

Edit the canonical copy and rebuild rather than editing one notebook. If a **fourth** repeated
block appears, treat it as a signal that the lessons have become too coupled.

## Writing checkpoints

- Ask about behaviour the participant has just *seen*, not definitions.
- Prefer "why did it do X" and "what breaks if we remove Y" over "what does this API do".
- At least one per notebook should be answerable **only from a trace** — otherwise LangSmith
  stays decorative through all of Part 1 and then Part 2 asks people to live in it.
- One right answer, and the notebook must already contain the evidence for it.

## Regenerating notebooks

`scratch/` is gitignored and holds the generator scripts used to produce the current notebooks
(`nbkit.py` plus `build_NN.py`). They exist because hand-escaping JSON across 400+ cells is
error-prone.

**The `.ipynb` files are the source of truth.** If you edit a notebook directly, the generator
for it is stale — either port the change back or delete that generator.

## Setup

```bash
uv sync --group dev
uv run lefthook install
```

That installs the git hooks. You only need this if you are **editing** notebooks — running a
lesson needs nothing but Colab and a LangSmith key.

## Hooks

Configured in `lefthook.yml`.

**pre-commit**

| Job | What it does |
|---|---|
| strip notebook outputs | `nbstripout` on staged notebooks, then re-stages them |
| lint notebooks | `tools/check_notebooks.py` — badges, outputs, keys, cell syntax, structure |
| scan for secrets | `tools/scan_secrets.sh` over every staged file |

**pre-push** re-runs the notebook lint unconditionally, because the pre-commit job only fires
when a notebook itself changed — a change to `tools/` could otherwise break every notebook
without any hook noticing.

The strip job passes `--keep-metadata-keys cellView`. Do not drop it: `cellView: form` is what
collapses the bulk data cells in Colab, and losing it silently unfolds 200 lines of fixture data
into the middle of a lesson.

`git commit --no-verify` skips the hooks. Reasonable for a work-in-progress commit on a branch;
never do it to get past the secret scan.

## Before opening a PR

```bash
python3 tools/check_notebooks.py    # runs automatically on commit, but check early
```

Then actually run any notebook you changed, in Colab, from a fresh runtime. Static checks cannot
tell you that a model stopped calling the tool your lesson depends on.
